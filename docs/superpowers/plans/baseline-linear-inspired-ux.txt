Manual visual baseline
----------------------
Captured from an isolated Electron launch at 1440 x 900 with a temporary vault
and temporary user-data/database directories. Screenshots remain local under:
/var/folders/z6/4_g615_14xs8nyfbqxzhxxc80000gn/T/opal-linear-baseline-screenshots

Reviewed states:
- /files with no selection
- /files with markdown selected
- /files in an image-heavy gallery
- /explorer with an empty database
- /settings

Observed baseline:
- Global navigation is a thin top route switch, while both product routes
  render their own unrelated three-pane shells.
- /files spends multiple stacked rows on breadcrumb, filtering, density,
  sorting, count, and view controls before content.
- The details header advertises Modified, Size, and Kind, but ordinary rows
  expose only name and size.
- The permanent preview pane consumes roughly one quarter of the window when
  empty and is too narrow for comfortable markdown reading.
- Navigating from a selected markdown file into Photos leaves the old markdown
  preview visible, demonstrating that browse selection and preview state can
  diverge.
- /explorer presents a second tree/detail/sidebar grammar with a large empty
  center and permanently visible Related/Chat rail.
- Settings reads as a full-width web form and uses unrelated saturated green,
  purple, and red action styling.
- Surface levels, borders, typography, and selection states are too similar to
  establish a strong shell/content/inspector hierarchy.

No visual-regression assertions were added.
