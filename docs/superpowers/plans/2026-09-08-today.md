# Today Implementation Plan

**Goal:** Make the existing vault usable as Opal's daily homepage.

**Architecture:** Renderer feature `today` composes existing disk and Markdown APIs. Pure parsers separate authored journal text from routine-owned activity. Revision-checked writes preserve external updates.

**Spec:** `docs/superpowers/specs/2026-09-08-today-design.md`

**Constraints:** No vault migration, no connector calls, no personal-file edits during verification. Reuse the isolated `codex/core-ux` checkout that powers the user's app.

1. Add `dailyModel.ts` and unit tests: date validation, activity boundaries outside fenced code, digest brief, tasks, local photo links. Journal writes reread latest content and compare only authored journal; task writes verify the original source line before toggling.
2. Add `dailyFiles.ts`: discover eligible opened roots; load existing day, digest, tasks, triage, and explicitly dated photo folder; distinguish missing content from read errors. Create a requested missing log through the existing Markdown API and template.
3. Add `journalStore.ts`: retain drafts by file path, debounce autosave, serialize saves, preserve edits made during an in-flight write, expose retry/conflict state.
4. Add `TodayRoute.tsx`, `JournalPanel.tsx`, and styles: responsive two-column day layout, date/vault controls, read-only brief and timeline, editable journal, privacy preference/shortcut, tasks, photos, source links. Add component tests for privacy and initial states.
5. Add the Today route and sidebar entry; default root/fallback routes to Today. Run `npm test`, `npm run lint`, `npx tsc --noEmit`, and production builds. Inspect the running app. Commit the completed slice and report remaining limitations.
